# Shared API (`src/shared/`)

> Contract of the code used by both the content script and the popup. The export list is in [extension-architecture.md](extension-architecture.md).

- **Signatures are a contract**: `src/content/**` and `src/options/**` consume them through `@shared/*`. When a signature changes, update every caller in the same change.
- **No React and no page DOM structure** here; the code must run in a content script and in the popup. The background script (`src/background/background.ts`) imports `syncEnterpriseScripts` from here, so this code must also run in a service worker: no `window` or `document`.
- **Clipboard payload** ([clipboard-service.ts](../../src/shared/services/clipboard-service.ts)): `text/html` is `ESCAPED_BEFORE<a href="ESCAPED_URL">ESCAPED_LINK</a>ESCAPED_AFTER` (the three parts come from `LinkPayload.parts`; with no link segment `before` and `after` are empty and the whole text is the link, as in 2.0.0), `text/plain` is `TEXT — URL` (em dash with spaces; `TEXT` is `before + link + after`, without the template brackets). `LinkPayload` is `{ text, parts, html, plain, markdown }`, where `markdown` is `BEFORE[LINK](URL)AFTER` (`\`, `[` and `]` are escaped in the link text, and a trailing `!` or `\` of the text before the link, which would turn the link into an image or escape its bracket; before and after stay as typed, so a title's own Markdown such as `code` is kept). **Copy format** (`config.format`, `LinkFormat`): `copyLink` writes `html` + `plain` for `rich` (the default) and only `text/plain` = `markdown` for `markdown` (an HTML flavor would make chats paste a link instead of the source); `getFlavors` in clipboard-service.ts maps the format to the flavors. **Several links** (`buildLinksPayload(targets, config)` and `copyLinks(targets, config)`, used by the list selection): `html` is `<ul><li>LINK_HTML</li>...</ul>`, `plain` has one `- TEXT — URL` line per link, `markdown` one `- [LINK](URL)` line per link; the format picks the flavors exactly as for one link (rich: html + plain, markdown: plain only). Primary path: `navigator.clipboard.write` with `ClipboardItem`; fallback: `document.execCommand('copy')` with a one-shot `copy` listener. Both must be reachable from a user click.
- **Templates** ([template-service.ts](../../src/shared/services/template-service.ts)): `{{placeholder}}` tokens, whitespace inside the braces allowed, unknown placeholders left as is, an empty template falls back to the default for the link type. The result is plain text; escaping happens only in `buildLinkPayload`.
    - **Link brackets**: `renderTemplateParts(template, target)` returns `TemplateParts { before, link, after }`; `renderTemplate` returns `before + link + after` (no brackets). Brackets are read in the **template** before placeholders are filled, so brackets in titles (`[WIP] Fix`) are plain text. The first `[`…`]` pair is the link (a `[` inside it is literal); later brackets are literal; a `[` without a closing `]` is literal; `\[` and `\]` are literal brackets (any other backslash stays). Brackets are split off before placeholders are replaced, so a bracket can't cut through a placeholder (`{{pr_[number]}}` is not a placeholder). Without a segment, with an empty `[]` or when the link renders to whitespace only, the whole text is the link (the 2.0.0 behavior). Whitespace at the edges of the link moves outside it (into `before` / `after`), so the link never starts or ends with a space; the whole text is trimmed at both ends, inner spacing is kept. A template that renders to empty text (e.g. `[]`) falls back to the default template, like an empty one.
    - **Defaults** are `[PR {{pr_number}}]: {{pr_name}}`, `[Issue {{issue_number}}]: {{issue_name}}`, `[Discussion {{discussion_number}}]: {{discussion_name}}` and `[{{workflow}} #{{run_number}}]: {{run_name}}`. `LEGACY_DEFAULT_TEMPLATES` (only for pull requests and issues) holds the old defaults (`PR {{pr_number}}: {{pr_name}}` / `Issue {{issue_number}}: {{issue_name}}`) and `MAX_TEMPLATE_LENGTH` (500) is shared by the import and the popup fields.
    - **Conversion of old templates**: `convertLegacyTemplate(template, type)` (before 2.1.0 brackets were plain text): a template exactly equal to the old default becomes the new default; any other template gets every `[` and `]` escaped as `\[` / `\]` (backslashes stay as they are), so it renders exactly as in 2.0.0. It is used for stored data without the format marker (below) and for settings files of schema 1 and 2.
    - Besides the advertised placeholders, the aliases `{{number}}` and `{{title}}` work for every type (not shown in the popup hints).
    - **Placeholders** (`TEMPLATE_PLACEHOLDERS` lists them per type): `pr_number`, `pr_name` (pull requests), `issue_number`, `issue_name` (issues), and for both `owner`, `repo`, `url`, `ref` (`owner/repo#number`), `author`, `state` (`open`, `closed`, `merged`, `draft`), `labels`, `assignees` (joined with `, `), `milestone`; pull requests also have `head_branch` and `base_branch`. **Discussions**: `discussion_number`, `discussion_name`, `owner`, `repo`, `url`, `ref`, `author`, `category`. **Workflow runs**: `run_number` (the number shown as `#20481`, which is also `{{number}}`; the URL holds the run id), `run_name`, `workflow`, `branch`, `status`, `owner`, `repo`, `url` (no `ref`). Placeholders that exist for another type only (`{{labels}}` in a discussion, `{{ref}}` in a run) stay as typed. The detail values are optional fields of `LinkTargetModel` (`author`, `state`, `labels`, `assignees`, `milestone`, `headBranch`, `baseBranch`, `category`, `workflow`, `branch`, `status`) filled by the content script ([link-metadata-parser.ts](../../src/content/services/link-metadata-parser.ts)); a known placeholder whose field is missing renders as an empty string (spacing around it stays), a placeholder that does not exist for the type (`{{head_branch}}` on an issue) is left as typed. **Adding a link type** touches `LinkType`, `DEFAULT_CONFIG.templates`, `TEMPLATE_PLACEHOLDERS`, `serializeSettings` (it writes every type), `getPlaceholderValues`, the popup field and sample, the button label in `copy-button.ts`, the page detection and parsers, the test fixture `DEFAULT_STORED_CONFIG` and the docs; the settings file schema needs no bump because unknown template keys are ignored and missing ones keep their value. Add a placeholder in three places: the model field, `getPlaceholderValues` and `TEMPLATE_PLACEHOLDERS`, then the popup samples, `docs/templates.md` and LISTING.
- **Config** ([config-service.ts](../../src/shared/services/config-service.ts)): `ConfigModel` is `{ templates, format, shortcuts, display, filters }`. Stored in `chrome.storage.sync` under `hyperfriend-config`, merged over `DEFAULT_CONFIG`: templates only when strings; per known `ShortcutType`, `keys` through `normalizeShortcut` (else the default keys) and `enabled` when boolean (else the default); `format` when it is a known `LinkFormat` (else the default `rich`); `display.authorAvatars` when boolean; `filters` through `applyFilters` (`custom` first: `normalizeCustomChips` keeps the valid chips, drops repeated ids and keeps at most `MAX_CUSTOM_CHIPS` (10); then `chips`: `normalizeFilterChips(value, customIds)` keeps the ids of the catalog and of the existing custom chips **in the order given**, without repeats, so a deleted custom chip disappears from the list too; `sticky.drafts` when boolean; an empty `chips` list is valid); unknown keys are ignored. Data written by 2.9.x and older has no `filters` and loads with the default ones. Data written by 2.2.x and older has no `format` and loads as `rich`. Data written by 1.0.0 (`{ templates }` only) loads with the new shortcut and display defaults. **Template format marker**: every write stores the whole config plus the internal `templateFormat: 2` field (a sibling of `templates`, not part of `ConfigModel`). A stored object without it (1.x / 2.0.0) has its templates converted with `convertLegacyTemplate` on read; nothing is written on read, so the marker (and the converted templates) are stored with the next write. Template values passed to `setTemplates` / `importSettings` are already in the new syntax and are stored as given. All writes (and `reset`) run through one queue, so overlapping calls in a context can't lose updates. `get` never rejects. Writers: `setTemplate` (one template), `setTemplateBeforeClose` (one template when the page is closing: it starts from the last config this context read, wrote or got from `onChanged` instead of reading storage, so `storage.set` is called in the same task when the queue is idle; without a known config, or after `reset` or a failed write, it reads like `setTemplate`), `setTemplates` (several), `setFormat(format)` (an unknown value is ignored), `setShortcut(type, Partial<ShortcutBindingModel>)` (invalid keys are ignored), `setDisplay(Partial<DisplayModel>)`, `setFilters(Partial<FiltersModel>)` (`sticky` may hold one flag), `importSettings(SettingsImportModel)`: each is a single merged write of the full config. `reset` removes the whole stored key (templates, copy format, shortcuts, display and filters; the remembered state of the sticky chips is in `chrome.storage.local`, see below, and is left alone). `cloneConfig` / `cloneDefaultConfig` return independent copies (use them instead of building a config by hand). `toStoredConfig(config)` (exported from `@shared/services`) returns the value stored under `hyperfriend-config`: the complete config plus the `templateFormat` marker; every write goes through it, and the tests use it to seed storage in the extension's own shape (`storage.seedConfig`), so a change to the stored shape needs no test edit.
- **Shortcuts** ([shortcut-utils.ts](../../src/shared/utils/shortcut-utils.ts), [shortcut-constants.ts](../../src/shared/constants/shortcut-constants.ts)): `ShortcutBindingModel` is `{ keys, enabled }`. `keys` is normalized: modifiers in the order `Control`, `Alt`, `Shift`, `Meta`, then exactly one `KeyboardEvent.code` of the main key (`['Shift', 'KeyC']`), so shortcuts follow the physical key and any keyboard layout. A disabled binding keeps its `keys`. The allowed main keys are `SHORTCUT_MAIN_KEYS` (letters, digits, F1-F24, arrows, US punctuation, editing and navigation keys, numpad; no `Escape` or `Tab`).
    - `shortcutFromEvent(event)` builds the keys of a key press (`null` for a lone modifier or a disallowed key). `normalizeShortcut(value)` validates untrusted data (storage, imported files) and **requires at least one modifier** and rejects `BROWSER_RESERVED_SHORTCUTS`; it returns the canonical order or `null`. `shortcutsEqual` ignores modifier order; `matchesShortcut(event, keys)` is an exact match.
    - Display: `formatShortcutParts(keys, isMac?)` (`['⇧', 'C']` on Mac, `['Shift', 'C']` elsewhere), `formatShortcut` (`⇧C` / `Shift+C`), `toAriaKeyShortcuts` (WAI-ARIA format, e.g. `Shift+C`), `isMacPlatform`.
    - `validateShortcut(keys, type, all)` returns `{ ok: true, warning? }` or `{ ok: false, error }` with short user-facing messages: no modifier (wording depends on `isMacPlatform()`), a combination in `BROWSER_RESERVED_SHORTCUTS` ("This shortcut is used by the browser."), the same keys as another **enabled** Hyperfriend shortcut ("Another Hyperfriend shortcut already uses these keys."), and, as warnings only, a combination in `GITHUB_SHORTCUTS` ("GitHub also uses this shortcut.") or in `TEXT_NAVIGATION_SHORTCUTS` (`Shift` plus Space, an arrow, Home, End, PageUp or PageDown: "This shortcut is used for scrolling or selecting text."). Extend the two named lists when a combination turns out to collide.
- **Settings import/export** ([settings-transfer-service.ts](../../src/shared/services/settings-transfer-service.ts), model `SettingsFileModel`): `serializeSettings(config, now?)` writes pretty JSON (2 spaces, trailing newline) `{ app: "hyperfriend", schemaVersion: 5, exportedAt, templates, format, shortcuts, display, filters }`; the file name is `SETTINGS_FILE_NAME` (`hyperfriend-settings.json`). `parseSettings(text)` returns `{ ok: true, settings }` (a `SettingsImportModel` with optional `templates`, `format`, `shortcuts`, `display`, `filters`) or `{ ok: false, error }` with a short user-facing message: at most 64 KB (the popup also checks `file.size` before reading), valid JSON object, `app` must be `hyperfriend`, `schemaVersion` 1, 2, 3, 4 or 5 (a higher one means "created by a newer version", which is also what 2.2.1 and older say about a 4 file and 2.9.x and older say about a 5 file). Version 5 adds `filters` (a `filters` field in a version 4 or older file is ignored). Version 4 adds `format`; version 3 is the `[link]` syntax and has none (a `format` field in a version 3 file is ignored): **templates of versions 1 and 2 are converted** with `convertLegacyTemplate` (old default to new default, other templates get their brackets escaped; the 500 character limit is checked on the file's text, before conversion). Rules:
    - **Templates** (all versions): an object, only known `LinkType` keys read, each value trimmed and then a single line of text (no line breaks or control characters) of at most 500 characters (error: `Template "<key>" must be a single line of text up to 500 characters.`). In versions 3 and 4 an escaped bracket (`\[`, `\]`) counts as one character, because converted old templates get those backslashes; `serializeSettings` writes every template through `toSingleLineTemplate` (control characters become spaces), so an exported file always imports again. A version 1 file (1.0.0, templates only) needs at least one template; in versions 2 to 4 the section is optional.
    - **Format** (version 4): `"rich"` or `"markdown"` (error: `Format must be "rich" or "markdown".`).
    - **Shortcuts** (versions 2 to 4): an object, only known `ShortcutType` keys read, each value an object with `keys` accepted by `normalizeShortcut` (stored normalized) and a boolean `enabled` (error: `Shortcut "<type>" is not valid.`). A binding whose keys are in `BROWSER_RESERVED_SHORTCUTS` is skipped instead (the shortcut keeps its current keys, the rest of the file imports), because the list grows between versions and an older file may hold a combination that is reserved now; a stored binding with such keys falls back to the default keys on read.
    - **Filters** (version 5): an object whose parts are optional. `custom` must be a list of at most `MAX_CUSTOM_CHIPS` (10) chips, each checked by `validateCustomChip` (id `custom-` + 8 lower case letters or digits, unique in the list; name one line of up to 30 characters and 48 bytes; icon from `CUSTOM_CHIP_ICONS`; colour from `CHIP_COLOURS`; filter by `parseCustomQuery`) and stored cleaned (errors: `Filter setting "custom" must be a list of chips.`, `... must hold up to 10 chips.`, `Custom chip id "<id>" is used twice.`, and a message that names the chip). `chips` must be a list of strings without repeats, each a catalog id or shaped like a custom id (an id no chip has is dropped when the settings are merged, because the file may name a chip the user made earlier), in the order of the bar (error: `Filter setting "chips" must be a list of known filter names.`). `sticky` an object whose `drafts` is a boolean (error: `Filter setting "sticky" must hold true or false values.`); other keys, such as a `bots` list of an earlier build, are ignored. A `filters` section that is not an object fails with `The "filters" section of the file is not valid.`
    - **Display** (versions 2 to 5): an object, `authorAvatars` must be a boolean (error: `Display setting "authorAvatars" must be true or false.`).
    - A version 2 to 5 file needs at least one setting (`The file does not contain any settings.`). Anything missing from the file keeps its current value; `configService.importSettings` applies the result with one merged storage write. When the schema changes, bump `schemaVersion` and keep reading older versions.
- **Quick filter logic** ([filter-query.ts](../../src/shared/utils/filter-query.ts), catalog `FILTER_CHIPS` in [filter-chips.ts](../../src/shared/constants/filter-chips.ts)): pure functions, no DOM and no `chrome.*`. A search text is split into tokens at spaces outside double quotes (`tokenizeQuery`); a token's key is its qualifier in lower case with the leading `-` kept (`getTokenKey`: `-is:draft` is `-is`, free text has none). A chip has `tokens` (fixed; the drafts chip has none), an `icon` (Octicon name) and `facets` (token keys it replaces). `toggleChip`: an active chip (all its tokens present, ignoring case) removes its tokens; an inactive one removes the tokens of its facets, then adds its own. The drafts chip cycles `any` → `hide` (`-is:draft`) → `only` (`is:draft`) → `any` (`getDraftState` also reads `draft:false` / `draft:true`). In a grouped query (a parenthesis, `OR`, `AND` or `NOT` among the tokens) no facet tokens are removed, because one of a group can not be taken out alone; only the chip's own tokens are added or removed. `applyRememberedState(tokens, { drafts }, filters)` returns the tokens with the remembered drafts state added, or `null`: it needs the sticky setting on **and** the chip shown, and leaves a query that already has a draft token. `readQuery(search)` and `buildSearch(search, tokens)` read and write the `q` parameter (`buildSearch` drops `page`, keeps other parameters). `DEFAULT_QUERY` is `is:pr state:open`. Adding a chip touches the `FilterChipId` enum (the value is permanent: it is stored and exported), `FILTER_CHIPS`, the docs and the tests; the default list is `DEFAULT_FILTER_CHIPS`, the default bots `DEFAULT_FILTER_BOTS`.
- **Custom chips** ([custom-chips.ts](../../src/shared/utils/custom-chips.ts), lists in [filter-chips.ts](../../src/shared/constants/filter-chips.ts)): `FilterChipModel` has `id: string`, `colour: ChipColour` and `facetTokens`; a `CustomChipModel` is `{ id, label, icon, colour, query }`. `parseCustomQuery(text)` reads the filter (trimmed, one line without control characters, U+2028/2029 or bidirectional controls, at most 200 characters **and 200 bytes of its JSON string** (`byteLength`: a quotation mark and a backslash count twice, as `chrome.storage.sync` counts), at most 10 words, closed quotation marks, no group word (`isGroupToken`) and no `is:pr`/`is:issue`/`type:pr`/`type:issue`, repeated words removed ignoring case) and returns the words and the cleaned text; `parseCustomLabel` the name (30 characters and 48 JSON bytes). `validateCustomChip(raw, lenient)` is strict for the import and the popup; `normalizeCustomChips` (storage) calls it with `lenient`: an icon this build does not know but with the shape of one (`[a-z0-9-]`, up to 40) is kept and an unknown colour becomes `default`, so a chip made by a later version is not lost when this version writes the settings (the lookups of icons skip unknown names). The limits are in bytes too because `chrome.storage.sync` allows 8,192 bytes per item and the whole config is one item (key and JSON text); `tests/unit/custom-chips.spec.ts` serializes the usual worst case (4 templates of 500 plain characters, 10 chips at the limits) and asserts it stays under 8,192. Templates full of escapes or non-English text are larger, so **`updateConfig` measures the key and the JSON of every write and throws `ConfigTooLargeError` (`bytes`, `limit`) before `storage.set`** (limit: `storage.QUOTA_BYTES_PER_ITEM`, else 8,192); nothing is written. The Filters tab and the import show `These settings are too large for the browser to sync (8 KB)...`; other writers show their generic error. `deriveFacets(tokens)` makes the conflict rules: single-value keys (`status`, `review`, `base`, `head`, `milestone`, `project`, `sort`, `language`) replace their own key; a token whose key is in `ROLE_FACETS` replaces the whole "who" group; a state word (`is:open`, `is:closed`, `is:merged`, `is:unmerged`, `state:open`, `state:closed`, `state:merged`) puts the state words into `facetTokens` (exact tokens, ignoring case, that `toggleChip` removes) so it also replaces the `state:open` of the list; everything else is additive. `toChipModel(custom)` gives the catalog shape (`kind: 'tokens'`, `description` `Adds <query>`), `resolveChips(filters)` returns the chips of `filters.chips` in order, skipping ids no chip has. The ids are made in the popup (`crypto.getRandomValues`, `custom-` and 8 characters of `0-9a-z`), never reused for another chip.
- **Edge cases to keep handled**: missing `chrome.storage`, storage errors, empty or odd templates, titles with HTML special characters, rejected clipboard writes.

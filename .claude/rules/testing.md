# Tests (Playwright)

> Conventions for the test suite. How to write, run and debug tests: the [playwright skill](../skills/playwright/SKILL.md). The test standard (rules and severities) is [e2e-review/references/rules.md](../skills/e2e-review/references/rules.md).

- **Write to the standard.** Every new or changed test follows the rules in the standard (SCN, AST, DATA, SYNC, STY, EXT, UNIT). When a rule and existing test code disagree, the rule wins.
- **Review before commit.** After writing or changing tests, run the `e2e-reviewer` agent (`/e2e-review`), fix every Critical and Major finding, and decide the Minor ones explicitly. Reference specs that others copy (the Pull Request spec) must come out of review clean.
- **Three test projects** (`playwright.config.ts`): `unit` (pure `src/shared`, no browser; `npm run test:unit`), `e2e` (built extension in Playwright's bundled Chromium, headless, GitHub snapshots, no network; `npm run test:e2e`) and `live` (smoke on real github.com `react/react`; `npm run test:live` = `HYPERFRIEND_LIVE=1 playwright test --project=live`, on demand and in the daily `markup.yml` workflow, never part of `npm test`, `/verify` or push CI). A setup project `dist` (`tests/setup/dist.setup.ts`) runs `npm run build` before `e2e` and `live`, so the npm scripts do not build themselves and a plain `npx playwright test` (and the Playwright agents) always runs on the current sources. `live` is defined only when `HYPERFRIEND_LIVE` is set, so nothing else reaches the network. `npm test` = `playwright test --project=unit --project=e2e`. Never add network access to `unit` or `e2e`. First time: `npx playwright install chromium`.
- **CI**: `.github/workflows/build.yml` runs `npm run test:unit` in job `build` (Node 22, 24, 26) and `npm run test:e2e` in job `e2e` (Node 24, Playwright's Chromium installed with `npx --no playwright install --with-deps chromium`, so the browser matches the installed package). `.github/workflows/markup.yml` (daily 05:00 UTC and manual) refreshes the snapshots, commits them to `master` as `github-actions[bot]` when they changed, then runs `npm run test:e2e` and `npm run test:live`; on failure it opens (or comments on) one `markup-drift` issue. Snapshots that break the tests are therefore already on `master`, and push CI stays red until the selectors or tests are fixed (by design). With `CI` set the config forbids `test.only` and adds the `github` reporter. The `e2e` job and `markup.yml` upload `playwright-report/` and `test-results/` on failure. Details: [docs-and-ci.md](docs-and-ci.md).
- **Fixtures**: specs import `test` and `expect` from `tests/e2e/fixtures/extension.ts` (fixtures `page`, `context`, `extensionId`, `openOptions`, `storage.seedConfig` / `setRawConfig` / `getConfig`, `readClipboard`, `writeClipboardSentinel`, `normalizeHtml`, `recordKeys`, option `githubRoutes`; function `readyForShortcut`) and `PAGES`, `snapshotUrl`, `snapshotItems`, `firstPlainItem`, `rowOf`, `titleButton`, `elementBeforeTitleButton`, `snapshotHtml` from `fixtures/github.ts` and `DEFAULT_STORED_CONFIG` from `fixtures/defaults.ts` (the literal defaults for expected stored values; never build an expected value from `DEFAULT_CONFIG` / `cloneDefaultConfig()`); the Pull Request specs are the reference for new specs; the API is described in the [playwright skill](../skills/playwright/SKILL.md#fixtures). Expected item numbers, titles and authors come from `snapshotItems` / `firstPlainItem(path)` (the first item whose title has no HTML special characters), not from the page under test and not from fixed rows: the lists change with every refresh. Data-dependent tests skip with a reason when the data is missing. A known product gap is a `test.fail()` test with an `issue` annotation that links the GitHub issue; it fails on purpose until the bug is fixed, then the marker is removed. The toast element exists only after first use: assert its absence with `toHaveCount(0)`. The context fixture fails a test when the extension logs a console or page error, when the extension did not load, or when a request has no snapshot or routing rule. Retries are 0 by design; traces are kept on failure.
- **Lazy avatars and snapshot layout**: snapshots have no GitHub CSS and avatars load lazily, so scroll the row into view before asserting on its avatar image.
- **Arrange state through storage and fixtures** (`storage.seedConfig(overrides)`; `setRawConfig` only for upgrade tests), not through the popup UI, unless the popup is under test. Each test starts from a clean context.
- **Snapshots** of GitHub pages (`tests/e2e/fixtures/pages/`, repository `react/react`, formerly `facebook/react`: pull request list, PR 9713 with its two tabs, issue list, issue 10, two search pages) are fixtures, looked up by path + query: scripts, comment and description bodies, tokens, nonces and email addresses removed, no personal data; refreshed by `markup.yml` daily and by hand with `npm run test:snapshots` (`capture-pages.mjs`, needs network; it waits for a stable DOM, numbers random ids in document order and drops per-request metadata, so unchanged pages give unchanged files; it fails when a forbidden pattern remains); review a manual refresh before commit; excluded from Prettier (`.prettierignore`).
- **Chrome only**: Playwright cannot load extensions into Firefox; never claim Firefox coverage from these tests.
- Tests are TypeScript, follow the repository style (tabs, block `if`, English comments), import shared code through `@shared/*`, and are linted and type-checked with the rest of the code: `npm run lint` runs ESLint (Node globals, type-aware `no-floating-promises`, `eslint-plugin-playwright` rules; the ones the standard rates Critical or Major are errors) over `tests/` (`.ts` and `.mjs`) and `playwright.config.ts`, and `npm run typecheck` also checks `tests/` (`tests/tsconfig.json`).
- **Playwright test agents**: `playwright-test-planner`, `-generator` and `-healer` in `.claude/agents/` and the `playwright-test` MCP server in `.mcp.json` are generated by `npx playwright init-agents --loop=claude --project=e2e`. Regenerate them after every Playwright update; do not hand-edit them. The command **overwrites `.mcp.json`**: re-add the `chrome-devtools` server afterwards (`git diff .mcp.json`). Seed: `tests/e2e/seed.spec.ts` (generated prompts mention `tests/seed.spec.ts`); plans go to `specs/`. Their output must follow this rule and pass `/e2e-review` like hand-written tests.
- When the suite layout, fixtures or npm scripts change, update this rule, the playwright skill, `README.md`, the `/verify` and `/release` skills and the `qa-engineer` checklist.

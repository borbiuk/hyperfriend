# Docs, CI and releases

> Conventions for the user-facing docs, GitHub automation and release tagging.

## Docs

- Describe the code as it is: read `package.json`, `public/manifest*.json`, `src/**` and `webpack/**` before writing about them. Every command, script name, path, placeholder and manifest value must match the code.
- `README.md`: features (copy button, keyboard shortcut, avatars, templates, shortcut settings, settings file format v2 with the v1 note), popup tabs, placeholder table, supported pages, development setup (Chrome Load unpacked `dist/`, Firefox `about:debugging` with `dist-firefox/manifest.json`), npm scripts, file structure, tooling notes. Store links stay "coming soon" until the extension is published.
- `LISTING.md`: store text with privacy (no data collection, no analytics; the only network traffic is the author avatar images from GitHub's own avatar server) and the permissions explained (`storage`; `scripting` and the optional access to a GitHub Enterprise domain the user adds; content script on github.com and `*.ghe.com`). Plain text with emoji bullets: no Markdown tables or code blocks.
- A user-visible change (shortcut, popup tab, setting, settings file field) goes into `README.md`, `LISTING.md` and `RELEASE_NOTES.md` together.
- `RELEASE_NOTES.md`: one `## x.y.z` heading per release, newest first. `scripts/tag-releases.sh` reads that heading pattern, so do not use it for anything else. `npm run lint:docs` (markdownlint with `.markdownlint-cli2.jsonc`, plus `scripts/check-docs.mjs`) fails on a broken relative link, a broken anchor in the same file, a heading that is not a version, a duplicate or unordered version, or a first heading that differs from the `package.json` version.

## CI and releases

- [build.yml](../../.github/workflows/build.yml) runs on pushes and pull requests to `master`. Job `build` (Node 22, 24 and 26, 15-minute timeout): `npm ci`, `npm audit signatures`, `check:versions`, `format:check`, both builds, `lint`, `lint:firefox`, `test:unit`. Job `checks` (Node 24, 10-minute timeout, runs once): `npm ci`, `npm run lint:docs`, `npm run lint:unused` (knip, `knip.jsonc`: every ignore has a comment; a new dead export or dependency fails the job). Job `e2e` (Node 24, 15-minute timeout): `npm ci`, `npx --no playwright install --with-deps chromium`, `npm run test:e2e`; on failure it uploads `playwright-report/` and `test-results/` as artifact `playwright-report-e2e` (14 days). Do not add `check:outdated` (new upstream releases would break CI at random). `concurrency` group `build-<ref>` cancels an older run of the same ref; checkout uses `persist-credentials: false` (these jobs never push).
- [pr-title.yml](../../.github/workflows/pr-title.yml) runs on pull requests to `master` (not for Dependabot) and calls `scripts/check-pr-title.mjs`: upper case first letter, at most 72 characters, no trailing period, no WIP, `fixup!` or `squash!`. The title goes in through `env` (`PR_TITLE`), never into the `run:` text. Pushed commits are not checked, because a bad title on `master` cannot be fixed without rewriting history; keep commit titles to the same rules by hand.
- [markup.yml](../../.github/workflows/markup.yml) (workflow `github-markup`) runs daily at 05:17 UTC (not at minute 0, the busiest scheduler time) and on `workflow_dispatch`, never on push or pull request. Top-level `contents: read`; the job has `contents: write` (it commits and pushes snapshots) and `issues: write` (the drift issue); `concurrency` group `github-markup` allows one run at a time. Steps: `npm ci`, Playwright Chromium, `npm run test:snapshots`; if `tests/e2e/fixtures/pages` changed, commit "Refresh GitHub page snapshots" as `github-actions[bot]` (Husky disabled with `HUSKY=0`) and push to `master`; then `npm run test:e2e` on the fresh snapshots and `npm run test:live` (it runs also when e2e failed, with `PLAYWRIGHT_HTML_OUTPUT_DIR=playwright-report-live` and `--output=test-results-live`, so it does not replace the e2e report). Job timeout 40 minutes. A push made with the workflow token does not trigger `build.yml`, which is why the workflow runs the tests itself. On any failure it uploads `playwright-report-markup` (14 days) and opens one issue labelled `markup-drift` ("Tests fail on the current GitHub markup"), or comments on the open one; close the issue after fixing the selectors. No AI agents are involved.
- [codeql.yml](../../.github/workflows/codeql.yml) (advanced setup, so GitHub's "Default setup" for code scanning must stay off) analyzes `javascript-typescript` and `actions` on pushes and pull requests to `master` and weekly (`build-mode: none`, config in `.github/codeql/codeql-config.yml` ignores the page snapshots and build output). [dependency-review.yml](../../.github/workflows/dependency-review.yml) fails a pull request that adds a high severity vulnerability or a license outside its allow list (the list is the set used by `package-lock.json`; a new license needs a deliberate addition; needs the dependency graph on). [scorecard.yml](../../.github/workflows/scorecard.yml) runs OpenSSF Scorecard weekly and on `master` pushes and publishes to the Security tab; keep its job shape (read-only top level, `security-events` and `id-token` on the job, only approved actions) or publishing is refused.
- **By design**, snapshots that make tests fail are already on `master`: every following push and pull request stays red in `build.yml` until the selectors in `src/content` and the tests are fixed ([github-dom-selectors.md](github-dom-selectors.md), [testing.md](testing.md)).
- **Pinned actions**: every `uses:` is a full commit SHA with the tag in a comment (`actions/checkout@<sha> # v7.0.1`). [dependabot.yml](../../.github/dependabot.yml) opens weekly pull requests for `npm` and `github-actions` (7-day cooldown; `typescript`, the TypeScript 6 compat alias, never gets a major update). In CI `playwright.config.ts` sets `globalTimeout` 10 minutes (a hang ends as a test failure before the job timeout, so the report is uploaded) and `workers: 2`.
- Workflows use least-privilege `permissions` (top-level `contents: read` everywhere; write scopes only on the job that needs them: `markup.yml`, `codeql.yml` `security-events`, `scorecard.yml` `security-events` and `id-token`; `persist-credentials: false` on every checkout that does not push) and reference only existing npm scripts. The Playwright browser is installed with `npx --no playwright install`, so it is the version of the installed `@playwright/test` package (a Playwright bump needs no workflow change). With `CI` set, `playwright.config.ts` forbids `test.only` and adds the `github` reporter.
- `scripts/tag-releases.sh` finds the commit by the `version` in `public/manifest.json` and creates tags only locally. Test it with `DRY_RUN=1` only.
- The whole release flow (version bump, release notes, commit and zips, push, CI, annotated tag, GitHub Release with `hyperfriend-{chrome,firefox}-x.y.z.zip`) is the `/release` skill: [release/SKILL.md](../skills/release/SKILL.md). Update it when this process changes.

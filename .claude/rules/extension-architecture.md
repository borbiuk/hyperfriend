# Extension architecture (MV3, Chrome + Firefox)

> Architecture rules for the Hyperfriend MV3 extension and its build constraints.

- **Entry points and responsibilities**
    - `src/content/content.ts`: content script injected into `https://github.com/*` and `https://*.ghe.com/*` (and the granted Enterprise Server domains). Adds copy buttons (Pull Requests, Issues, Discussions, workflow runs), author avatars and keyboard shortcuts. Must not import React. Structure: `services/` (`page-detector`, `link-target-parser`, `link-metadata-parser`, `button-injector`, `page-observer`, `config-store`, `shortcut-service`), `components/copy-button.ts`, `icons/octicons.ts`, `styles/copy-button.css`, `styles/tooltip.css`, `styles/toast.css` and `styles/avatar.css`, `components/tooltip.ts` (shared tooltip and live region), `components/toast.ts` (shared toast, `data-hyperfriend="toast"`), `services/avatar-injector.ts` (author avatars in Pull Request lists, switched by `display.authorAvatars`), `services/selection-service.ts` and `components/selection-bar.ts` + `styles/selection-bar.css` (Shift+click multi-select in lists: the selected row buttons, the bottom bar and the list copy), `shortcut/` (`shortcut-handler.ts` interface, one handler per shortcut, e.g. `copy-link-shortcut-handler.ts`). `content.ts` builds `ConfigStore`, `SelectionService`, `ButtonInjector`, `ShortcutService` (with the handler registry), `AvatarInjector` and `PageObserver`; the initial scan and the shortcut listener start only after the config has loaded. Details: [github-dom-selectors.md](github-dom-selectors.md).
    - `src/options/options.tsx`: toolbar popup (`public/options.html`), React + Primer React, `ThemeProvider` with `colorMode="auto"` (light/dark) and the `@primer/primitives` light/dark CSS; `options.html` sets `data-color-mode="auto"` on `<html>` and a 400 px body. The link type switch shows the Octicons (`GitPullRequestIcon`, `IssueOpenedIcon`, `CommentDiscussionIcon`, `PlayIcon`, `aria-hidden`) from `@primer/octicons-react`. The UI is three tabs (`UnderlinePanels` from `@primer/react/experimental`): Templates, Shortcuts, General. Components: `options-app.tsx` (header, tabs, footer), `templates-panel.tsx` (link type switch), `shortcuts-panel.tsx`, `general-panel.tsx` (settings view and the GitHub Enterprise Server screen, `enterprise-section.tsx`), `template-field.tsx`, `token-editor.tsx` (the template editor with placeholder chips), `shortcut-row.tsx`, `key-chips.tsx`, `settings-section.tsx`, `settings-actions.tsx` (export, import, reset all); `constants/shortcut-items.ts` (`SHORTCUT_ITEMS`); hooks `use-config.ts`, `use-view-mode.ts` (popup or tab); `utils/options-hash.ts`, `utils/template-tokens.ts` (placeholder tokens, link range, placeholder groups), `utils/describe-shortcut.ts`, `utils/download-text.ts` (Blob + temporary `<a download>`, so no `downloads` permission); `styles/tabs.css`, `styles/templates.css`, `styles/general.css`. The same `options.html` is also the options page (`options_ui` with `open_in_tab: true`, in both manifests); in a tab the 400 px panel is centered. Firefox closes the popup when the download panel or the OS file picker opens, so there both Export and Import open that tab on the General tab (`chrome.tabs.create` with `options.html#general`, no extra permission). Details: [popup.md](popup.md).
    - `src/types/global.d.ts`: ambient declarations (`declare module '*.css';` for side-effect CSS imports).
    - `src/shared/`: models, constants, services and utils used by both entrypoints.
    - `src/background/background.ts`: the only background code (a service worker in Chrome, an event page in Firefox). It listens to `runtime.onInstalled`, `runtime.onStartup` and `permissions.onAdded` / `onRemoved` and runs `syncEnterpriseScripts` (queued, so two events never register a script twice): registered content scripts can be lost on an update, and the permission prompt closes the popup before anything in it could register the script. Keep it that small; the content script and the popup read and write `chrome.storage.sync` through `configService`.

- **Shared API (`@shared/*`)**
    - `@shared/models`: `LinkType` (`pull-request`, `issue`, `discussion`, `workflow-run`), `LinkTargetModel`, `ConfigModel` (`templates`, `format`, `shortcuts`, `display`), `LinkFormat` (`rich`, `markdown`), `ShortcutType`, `ShortcutBindingModel`, `DisplayModel`, `SettingsFileModel` (schema version 4), `SettingsImportModel`.
    - `@shared/constants`: `DEFAULT_CONFIG`, `TEMPLATE_PLACEHOLDERS`, `CONFIG_STORAGE_KEY` (`hyperfriend-config`), `SHORTCUT_MAIN_KEYS`, `BROWSER_RESERVED_SHORTCUTS`, `GITHUB_SHORTCUTS`, `TEXT_NAVIGATION_SHORTCUTS`.
    - `@shared/services`: `parseEnterpriseHost`, `listEnterpriseHosts`, `requestEnterpriseHost`, `removeEnterpriseHost`, `syncEnterpriseScripts`, `toOriginPattern` (GitHub Enterprise, `enterprise-service.ts`), `renderTemplate`, `configService` (`get`, `setTemplate`, `setTemplateBeforeClose` (pagehide / hidden popup: no storage read), `setTemplates` (one merged write), `setFormat`, `setShortcut`, `setDisplay`, `importSettings` (one merged write), `reset` (all settings), `subscribe`), `cloneConfig`, `cloneDefaultConfig`, `buildLinkPayload`, `buildLinksPayload`, `copyLink`, `copyLinks`, `serializeSettings`, `parseSettings`, `toSingleLineTemplate`, `SETTINGS_FILE_NAME` (settings import/export, [shared-api.md](shared-api.md)).
    - `@shared/utils`: `escapeHtml` and the shortcut helpers (`MODIFIER_KEYS`, `isMacPlatform`, `shortcutFromEvent`, `normalizeShortcut`, `shortcutsEqual`, `matchesShortcut`, `formatShortcutParts`, `formatShortcut`, `toAriaKeyShortcuts`, `validateShortcut`).
    - `copyLink` must be called synchronously inside the click or `keydown` handler (user activation). The content script preloads the config in `ConfigStore` and keeps it fresh with `configService.subscribe`; a shortcut handler reads the config synchronously from `ConfigStore`.
    - Debounce `configService.setTemplate` while typing (about 300 ms) to respect `chrome.storage.sync` write quotas; the popup flushes a pending save on blur, `pagehide`, `visibilitychange` and unmount, and Reset cancels pending saves first. On `pagehide` and a hidden popup the flush uses `setTemplateBeforeClose`, which writes over the last config this context knows instead of reading storage first: the popup is torn down before a read reply arrives, so a read-modify-write there never reached `storage.set`.
    - `copyLink` falls back to `execCommand('copy')` with a one-shot `copy` listener on `window` (capture phase, `stopImmediatePropagation`) so page handlers cannot override the payload. The fallback runs synchronously when the Clipboard API is missing.

- **How to add a new keyboard shortcut** (checklist; the key combination is data in the config, the action is code in the content script)
    1. Add a value to the `ShortcutType` enum in `src/shared/models/shortcut-type.ts` (the string value is the key in storage and in settings files, so it is permanent).
    2. Add its default binding (`{ keys, enabled }`) to `DEFAULT_CONFIG.shortcuts` in `src/shared/constants/default-config.ts`. The default must pass `validateShortcut`; `cloneConfig`, `serializeSettings` and the import code iterate over `ShortcutType`, so they need no change.
    3. Add a handler in `src/content/shortcut/` implementing `ShortcutHandler` (`type`, `isAvailable(kind, location)`, `handle(event)`) and register it in the `ShortcutService` list in `src/content/content.ts`. `handle` runs synchronously inside `keydown`; start a clipboard write without an `await` before it.
    4. Add a row to `SHORTCUT_ITEMS` in `src/options/constants/shortcut-items.ts` (title and short description of where it works).
    5. Update the docs: `docs/usage.md` (and `docs/templates.md` for settings file fields), `LISTING.md`, `RELEASE_NOTES.md`, and the matching rules (this file, [shared-api.md](shared-api.md), [popup.md](popup.md), [github-dom-selectors.md](github-dom-selectors.md)).

- **Manifests**
    - Two manifests: `public/manifest.json` (Chrome) and `public/manifest.firefox.json` (Firefox). Keep them identical except `browser_specific_settings` (`gecko` and `gecko_android`) in the Firefox one and `background` (`{ "service_worker": "background.js" }` in Chrome, `{ "scripts": ["background.js"] }` in Firefox). Any change goes into both.
    - Firefox only: `browser_specific_settings.gecko` with `id` `hyperfriend@borbiuk`, `strict_min_version` `140.0` and `data_collection_permissions` `{ "required": ["none"] }` (this key needs Firefox 140+), plus `browser_specific_settings.gecko_android.strict_min_version` `142.0` (Firefox for Android).
    - Permissions: `storage` and `scripting` (to register and start the content script on the Enterprise domains), no `host_permissions`, `optional_host_permissions` `["https://*/*"]` (the broad pattern only makes a runtime request possible: the extension requests one exact `https://HOST/*` at a time, after the user typed that domain, and never a wildcard host). Content script `matches`: `https://github.com/*` and `https://*.ghe.com/*` (GitHub Enterprise Cloud with data residency; no setup, so `parseEnterpriseHost` refuses `*.ghe.com` and `listEnterpriseHosts` skips it). Both manifests also have `options_ui` `{ "page": "options.html", "open_in_tab": true }`.
    - **Network**: the extension makes no requests of its own (no `fetch`, no analytics). The only traffic is the author avatar `<img>` elements it adds to GitHub pages (`https://avatars.githubusercontent.com/{login}?size=32`, GitHub's own CDN). Do not add other remote resources.
    - Icon: `icons` and `action.default_icon` (16, 32, 48, 128) point to `assets/logo-*.png` in both manifests; `zip.sh` includes the same files. Sources are in `design/icon/`; the PNGs are generated by `./design/icon/render.sh`.
    - The version is edited only in `public/manifest.json`; the pre-commit hook syncs it to `package.json` and `manifest.firefox.json`.

- **Bundles**
    - Fixed file names (`content.js`, `options.js`), no hashes, no vendor or runtime chunks: manifests and `options.html` reference exact names.
    - `*.css` imports work in both entries (`style-loader` + `css-loader`), including CSS from `node_modules` (Primer).
    - Production builds drop `console.log`, `console.info` and `console.debug` (Terser `drop_console`); `console.warn` and `console.error` are kept, so use them for messages that must survive.

- **Imports**
    - Prefer the `@shared/*` alias for cross-area shared code (see `webpack/webpack.common.js` and `tsconfig.json`).
    - Avoid deep cross-area relative imports like `../../shared/...` when `@shared/...` exists.

- **Browser APIs**
    - Use the `chrome.*` namespace (Firefox MV3 supports it); no `browser.*` polyfill.
    - Verify Chrome API behavior with the `chrome-extensions` skill (plugin `modern-web-guidance`, enabled in `.claude/settings.json`) or on `developer.chrome.com`; Firefox differences are in [firefox.md](firefox.md) and on MDN.

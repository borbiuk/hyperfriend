# Toolbar popup (`src/options/`)

> Settings UI: React 19 + Primer React. Theming, entry and save timing are described in [extension-architecture.md](extension-architecture.md).

- **Width is 400 px** (set in `public/options.html` and `OptionsApp`); keep the layout compact.
- **Layout** (`options-app.tsx`): header (logo + "Hyperfriend"), three tabs, footer with the GitHub link on every tab. Tabs are `UnderlinePanels` from `@primer/react/experimental` (`Templates`, `Shortcuts`, `General`), one panel component each (`templates-panel.tsx`, `shortcuts-panel.tsx`, `general-panel.tsx`).
    - **Panels stay mounted.** The hidden ones keep their layout box (`styles/tabs.css`: all panels share one grid cell, hidden ones are `visibility: hidden`), so the popup is always as tall as the tallest tab and never jumps, and template fields keep their state when you switch tabs. Do not turn this into conditional rendering.
    - **URL hash** (`utils/options-hash.ts`, `parseOptionsHash`): comma- or `&`-separated, case-insensitive tokens; `templates`, `shortcuts` or `general` pick the first tab (default `templates`), `tab` forces the browser tab view (`use-view-mode.ts`; for manual tests). They combine: `#tab,general`. Unknown tokens are ignored. The hash only chooses the initial tab; it does not follow tab clicks.
- **Templates tab**: one field per link type: Pull Request and Issue, and, inside a native `<details>` "Discussions and workflow runs" that is closed at first (four fields would make the popup taller than Chrome's 600 px limit; the closed fields stay mounted), Discussion and Workflow run. Each `TemplateField` has an accessible label, placeholder hints from `TEMPLATE_PLACEHOLDERS` (not the hidden `{{number}}` / `{{title}}` aliases), a live preview built with `buildLinkPayload` for a sample item that carries every detail (author, state, labels, assignees, milestone, branches) that shows `parts.before`, the underlined `parts.link` (with a visually hidden "(link)") and `parts.after`, so it matches the pasted link, and autosave (about 300 ms) with a "Saved" status. One hint above both fields ("Put the part that should be the link in [square brackets]." in `templates-panel.tsx`) is referenced by each input through `aria-describedby`. No buttons here.
- **Shortcuts tab**: rows are driven by `SHORTCUT_ITEMS` (`constants/shortcut-items.ts`: `type`, `title`, `description`); a new `ShortcutType` needs a row (the "How to add a new keyboard shortcut" checklist in [extension-architecture.md](extension-architecture.md)).
    - `ShortcutRow`: title and description, a keys button, a `ToggleSwitch` (accessible label) and a "Reset" button that shows only when the keys differ from `DEFAULT_CONFIG`. Keys are `<kbd>` chips (`key-chips.tsx`, `formatShortcutParts`: `⇧C` symbols on Mac, `Shift`/`C` elsewhere); the accessible name spells the keys out (`utils/describe-shortcut.ts`).
    - **Recording**: click the keys button, then press the combination ("Press a shortcut…"; held modifiers show live). `keydown` is captured on the button (`preventDefault` + `stopPropagation`, so `Escape` doesn't close the popup). Lone modifiers are ignored, `Escape` cancels, `Tab` is left alone, blur cancels. The combination is read with `shortcutFromEvent`, checked with `validateShortcut` (errors stay in recording mode; a warning is shown but the keys are saved) and saved immediately with `configService.setShortcut`. The toggle saves `{ enabled }` and keeps the keys.
    - Messages live in always-mounted `role="alert"` (errors) / `role="status"` (warnings) regions. Hint under the rows: "Shortcuts don't work while you type in a text field."
- **General tab**: section "Copy format" (a Primer `RadioGroup` named "Copy format" with "Rich link" and "Markdown", saved at once with `configService.setFormat`, optimistic like the switch; the Templates preview shows the Markdown source in Markdown mode instead of the underlined link), section "Display" with the switch "Show author avatars" (caption "In pull request lists", saved at once with `configService.setDisplay`; the content script applies it live) and section "Settings" with Export, Import and "Reset all settings" (`settings-actions.tsx`). Messages appear under the buttons (success "Settings imported.", errors inline).
    - "Reset all settings" opens a `ConfirmationDialog` ("Reset all settings?", confirm "Reset"), then `configService.reset()` (templates, copy format, shortcuts and display). There is no `confirm()`.
    - Reset and Import cancel pending field saves first; Export flushes them first (the fields register their controls with `OptionsApp`). After a reset or import `applyStored` re-reads the config and bumps `syncEpoch`, so every tab (fields, rows) drops its local state.
    - Export builds `hyperfriend-settings.json` with `serializeSettings` and downloads it through a Blob and a temporary `<a download>` (`utils/download-text.ts`); no `downloads` permission.
    - Import rejects files over 64 KB (checked via `file.size`) before reading them. It reads a hidden `<input type="file" accept="application/json,.json">` with `file.text()`, validates with `parseSettings`, applies with one `configService.importSettings(result.settings)` call and refreshes the UI.
    - **Chrome**: Export and Import work directly in the popup.
    - **Firefox**: the popup closes when the download panel or the OS file picker opens, so **both Export and Import** there open the settings page in a tab on the General tab: `chrome.tabs.create({ url: chrome.runtime.getURL('options.html#general') })`, then `window.close()` on success (no new permission; `options_ui` with `open_in_tab` stays for the extensions manager). `use-view-mode.ts` tells the tab from the popup (`chrome.tabs.getCurrent()`; `#tab` forces tab mode for manual tests); in a tab the 400 px panel is centered.
- **Popups close when they lose focus** in both browsers: save on change and keep no unsaved state that matters. Subscribe to `configService` (`use-config.ts`) so changes made elsewhere show up.
- The old `footer-actions.tsx` is gone; the footer only holds the repository link.
- Check both light and dark themes, all three tabs, and the popup height when switching tabs.

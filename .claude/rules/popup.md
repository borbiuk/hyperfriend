# Toolbar popup (`src/options/`)

> Settings UI: React 19 + Primer React. Theming, entry and save timing are described in [extension-architecture.md](extension-architecture.md).

- **Width is 400 px** (set in `public/options.html` and `OptionsApp`); keep the layout compact.
- **Layout** (`options-app.tsx`): header (logo + "Hyperfriend"), four tabs, footer with the GitHub link on every tab. Tabs are `UnderlinePanels` from `@primer/react/experimental` (`Templates`, `Shortcuts`, `Filters`, `General`), one panel component each (`templates-panel.tsx`, `shortcuts-panel.tsx`, `filters-panel.tsx`, `general-panel.tsx`).
    - **Panels stay mounted.** The hidden ones keep their layout box (`styles/tabs.css`: all panels share one grid cell, hidden ones are `visibility: hidden`), so the popup is always as tall as the tallest tab and never jumps, and template fields keep their state when you switch tabs. Do not turn this into conditional rendering.
    - **URL hash** (`utils/options-hash.ts`, `parseOptionsHash`): comma- or `&`-separated, case-insensitive tokens; `templates`, `shortcuts`, `filters` or `general` pick the first tab (default `templates`), `tab` forces the browser tab view (`use-view-mode.ts`; for manual tests). They combine: `#tab,general`. Unknown tokens are ignored. The hash only chooses the initial tab; it does not follow tab clicks.
- **Templates tab** (`templates-panel.tsx`): a switch of the four link types (plain `<button>`s in a `role="group"` named "Link type", `aria-pressed`; PR, Issue, Discussion, Run, each with its Octicon; a dot and a visually hidden " (customized)" mark a template that differs from the default) and the field of the selected type. **All four `TemplateField`s stay mounted**: they share one grid cell (`styles/templates.css`, `.hyperfriend-fields`) and the inactive ones are `visibility: hidden`, so the tab keeps its height and each field keeps its state; the selected type is not stored (PR after every open). The tab must stay below Chrome's 600 px popup limit (about 597 px now): check the height after any change. Each `TemplateField` (`template-field.tsx`) has:
    - a label (`aria-labelledby` of the editor, e.g. "Pull Request link template"), "Reset to default" (only while the draft differs from `DEFAULT_CONFIG.templates`) and the "Saved" status;
    - the editor `TokenEditor` (`token-editor.tsx`): a `contenteditable` `role="textbox"` (`aria-multiline="false"`, `aria-invalid` after a failed save) that shows every known `{{placeholder}}` (`TEMPLATE_PLACEHOLDERS[type]`, exactly `{{name}}` without spaces) as a chip (`<span data-token contenteditable="false" role="img" aria-label="placeholder name">`, text `{{name}}`) and marks the link part (`findLinkRange`: first unescaped `[` to the next unescaped `]`, the same rule as the copy code) with a CSS Custom Highlight (`::highlight(hyperfriend-link-<type>)`, needs Chrome 105+ / Firefox 140+). React never renders its children: the DOM is rebuilt from the text (`buildNodes`) whenever it is not canonical (typed `{{name}}`, stray `<br>`, lost guard). Rules: the text is `textContent` without U+200B; a zero-width space "guard" stands before a first chip, between chips and after a last chip so the caret has a place; the caret is kept as a character offset (a chip counts as `{{name}}`); Backspace and Delete next to the caret work on the text (one press removes a whole chip); Enter, formatting and drops are blocked, a paste is plain text; control characters become spaces (`toSingleLineTemplate`) and the text is cut at `MAX_TEMPLATE_LENGTH`; IME composition is applied on `compositionend`. The element carries `data-value` (the clean template text) for tests. The editor is a text box, not an `<input>`: `toHaveValue` does not work on it, tests use `data-value`;
    - the hint "Text inside [brackets] becomes the link." (`aria-describedby`) and, after a failed save, an error row "Could not save. Your text is kept." with "Try again" (the always-mounted visually hidden `role="alert"` and `role="status"` regions keep announcing);
    - "Insert placeholder": quick chip buttons (`QUICK_PLACEHOLDERS` in `utils/template-tokens.ts`; `mousedown` is prevented so the caret stays in the editor) and a Primer `ActionMenu` "All placeholders" with all names of the type in groups (`groupPlaceholders`: Item, Repository, Branches, Details). Both insert `{{name}}` at the caret or in place of the selection (`TokenEditorHandle.insert`; the menu insert runs in a `setTimeout` because the menu returns the focus to its button);
    - "You will paste": a live preview built with `buildLinkPayload` for a sample item that carries every detail (author, state, labels, assignees, milestone, branches), showing `parts.before`, the underlined `parts.link` (with a visually hidden "(link)") and `parts.after`, or the Markdown source in Markdown mode, so it matches the pasted link; a note names the copy format and points to the General tab.
    - autosave (about 300 ms), flush on blur, `pagehide`, hidden page and unmount, `registerField` controls and the failed-save retry are unchanged from before the redesign (see [shared-api.md](shared-api.md) and [extension-architecture.md](extension-architecture.md)). No buttons other than the ones above.
- **Shortcuts tab**: rows are driven by `SHORTCUT_ITEMS` (`constants/shortcut-items.ts`: `type`, `title`, `description`); a new `ShortcutType` needs a row (the "How to add a new keyboard shortcut" checklist in [extension-architecture.md](extension-architecture.md)).
    - `ShortcutRow`: title and description, a keys button, a `ToggleSwitch` (accessible label) and a "Reset" button that shows only when the keys differ from `DEFAULT_CONFIG`. Keys are `<kbd>` chips (`key-chips.tsx`, `formatShortcutParts`: `⇧C` symbols on Mac, `Shift`/`C` elsewhere); the accessible name spells the keys out (`utils/describe-shortcut.ts`).
    - **Recording**: click the keys button, then press the combination ("Press a shortcut…"; held modifiers show live). `keydown` is captured on the button (`preventDefault` + `stopPropagation`, so `Escape` doesn't close the popup). Lone modifiers are ignored, `Escape` cancels, `Tab` is left alone, blur cancels. The combination is read with `shortcutFromEvent`, checked with `validateShortcut` (errors stay in recording mode; a warning is shown but the keys are saved) and saved immediately with `configService.setShortcut`. The toggle saves `{ enabled }` and keeps the keys.
    - Messages live in always-mounted `role="alert"` (errors) / `role="status"` (warnings) regions. Hint under the rows: "Shortcuts don't work while you type in a text field."
- **Filters tab** (`filters-panel.tsx`, `filter-chip-list.tsx`, `filter-chip-editor.tsx`, `chip-icon.tsx`, `styles/filters.css`, `constants/filter-chip-icons.ts`): two views in one grid cell like the General tab (`.hyperfriend-views`, both stay mounted, the inactive one is `visibility: hidden`; `key={session}`, a counter raised on every opening, gives every opening fresh fields). **List view**: section "Quick filters in pull request lists" with `FilterChipList` in a group that scrolls (`max-height: 248px`): the list **Chips shown in the bar** (`ul` with `aria-label`; each `li` has `data-chip-id`, is `draggable` and holds a grip, the icon, the name, `IconButton`s **Move X up** / **Move X down** (disabled at the ends; `data-action`), **Edit X** for custom chips and **Hide X from the bar**) and the list **Chips not shown in the bar** (**Edit X** and **Show X in the bar**, which appends the id). Reordering is native HTML5 drag and drop (`dragstart` sets `text/plain` because Firefox needs data, `dragover` and `drop` on the target row move the dragged id to the target's index, a border marks where the row lands: above the target when dragging up, below it when dragging down) plus the arrow buttons; a `role="status"` region says `X moved to position N of M`. **Focus**: a button that turns disabled after a move (the chip reached an end) or a row that leaves the list loses the focus, so an effect moves it to the nearest enabled button (`focusAfter`: the other arrow of the row, the next row's Hide button, the Hide button of a chip that was shown); a drop leaves the focus alone. When the editor closes the focus goes back to the Edit button that opened it, else to **Add a custom chip**; if the chip being edited is deleted elsewhere the view goes back to the list. Every change writes `configService.setFilters({ chips })` with an optimistic list and a pending counter (storage updates are followed only without a write in flight). Below the list: **Add a custom chip** (disabled with the text `Up to 10 custom chips` at the limit) and the section "Remember your choice on every list" with the `ToggleSwitch` "Remember the drafts filter" (`useOptimisticToggle`, disabled while Drafts is hidden). **Editor view**: a back button (`Filters`) and the heading `New chip` / `Edit chip`, **Name** (`maxLength` 30), **Icon** (a `radiogroup` of 36 native radio buttons drawn as icon buttons, `aria-label` the icon name), **Colour** (a `radiogroup` of 8 swatches, `aria-label` the colour name), **Filter** (monospace, hint with examples, `aria-describedby`, `aria-invalid` and a `role="alert"` line only while there is an error), a live preview chip (`.hyperfriend-chip-preview`, `data-colour`) and **Delete** (existing chips; the first click asks `Delete this chip?` with **Keep** and **Yes, delete**) and **Save** (both wait while a write is in flight). Enter in the name or the filter field saves. Save checks the name (`parseCustomLabel`) and the filter (`parseCustomQuery`) and writes `setFilters({ custom, chips })` in one write (a new chip is appended to `chips`, an edited one keeps its place); a refused write shows the too-large message (`ConfigTooLargeError`) or `Could not save. Try again.` The CSS classes of the editor are `hyperfriend-chip-editor*` on purpose: `hyperfriend-editor` is the template editor of the Templates tab. Colours are the Primer variables of the popup (`--fgColor-success`, ... through `data-colour`). The tab must stay below Chrome's 600 px popup limit (the `popup-tabs` spec checks it; the list view is about 441 px, the Templates tab is the other tall one): check the height after any change. The panel is remounted after an import or reset (`key={syncEpoch}`).
- **General tab** (`general-panel.tsx`, `styles/general.css`): two views in one grid cell (`.hyperfriend-views`; the inactive one is `visibility: hidden`, so the tab height never changes and **both stay mounted**): the settings and the GitHub Enterprise Server screen. The tab must stay below Chrome's 600 px popup limit (about 595 px now, the same as the Templates tab): check the height after any change.
    - Section "Copy format": two native radio buttons drawn as segments (`role="radiogroup"` named "Copy format", `name="copy-format"`, each `<input type="radio">` covers its label; `Rich link` and `Markdown`), saved at once with `configService.setFormat`, optimistic like the switch; a caption under it and a preview of the sample Pull Request (`SAMPLE_PULL_REQUEST` from `templates-panel.tsx`) built with `buildLinkPayload` from the user's own templates: the underlined link in Rich mode, the Markdown source in Markdown mode (the Templates preview shows the same).
    - Section "Options": a group with the row "Show author avatars" (caption "In pull request lists", Primer `ToggleSwitch`, saved at once with `configService.setDisplay`; the content script applies it live) and, below it, a second group with the button row "Enterprise Server domains" (caption "*.ghe.com works without setup", on the right "None added" or "N added", a chevron). The row opens the Enterprise screen; the count comes from `EnterpriseSection` through `onHostsChange`. The focus moves to the back button when the screen opens and back to the row when it closes.
    - **GitHub Enterprise Server screen** (`enterprise-section.tsx`): a "General" back button, the heading "GitHub Enterprise Server", a short explanation, the labelled field "Domain" with **Add**, the `role="alert"` / `role="status"` regions, and the list "Added domains" (max height 160 px, **Remove** per row). Same logic as before: `parseEnterpriseHost`, `requestEnterpriseHost` called from the click (the browser prompt needs the gesture), `removeEnterpriseHost`, `listEnterpriseHosts` refreshed on `chrome.permissions.onAdded` / `onRemoved`; Firefox opens the settings page in a tab instead of asking in the popup.
    - Section "Settings file" (`settings-actions.tsx`): a one-line explanation, **Export** and **Import** (small buttons), **Reset all settings** (an invisible danger button at the right of the same row) and the messages under them ("Settings imported.", errors inline).
    - "Reset all settings" opens a `ConfirmationDialog` ("Reset all settings?", confirm "Reset"), then `configService.reset()` (templates, copy format, shortcuts, display and filters). There is no `confirm()`.
    - Reset and Import cancel pending field saves first; Export flushes them first (the fields register their controls with `OptionsApp`). After a reset or import `applyStored` re-reads the config and bumps `syncEpoch`, so every tab (fields, rows) drops its local state.
    - Export builds `hyperfriend-settings.json` with `serializeSettings` and downloads it through a Blob and a temporary `<a download>` (`utils/download-text.ts`); no `downloads` permission.
    - Import rejects files over 64 KB (checked via `file.size`) before reading them. It reads a hidden `<input type="file" accept="application/json,.json">` with `file.text()`, validates with `parseSettings`, applies with one `configService.importSettings(result.settings)` call and refreshes the UI.
    - **Chrome**: Export and Import work directly in the popup.
    - **Firefox**: the popup closes when the download panel or the OS file picker opens, so **both Export and Import** there open the settings page in a tab on the General tab: `chrome.tabs.create({ url: chrome.runtime.getURL('options.html#general') })`, then `window.close()` on success (no new permission; `options_ui` with `open_in_tab` stays for the extensions manager). `use-view-mode.ts` tells the tab from the popup (`chrome.tabs.getCurrent()`; `#tab` forces tab mode for manual tests); in a tab the 400 px panel is centered.
- **Popups close when they lose focus** in both browsers: save on change and keep no unsaved state that matters. Subscribe to `configService` (`use-config.ts`) so changes made elsewhere show up.
- `options.tsx` passes `onUncaughtError` to `createRoot`: after an uncaught render error it logs it and shows a short `role="alert"` message instead of a blank popup.
- The old `footer-actions.tsx` is gone; the footer only holds the repository link.
- Check both light and dark themes, all four tabs, and the popup height when switching tabs.

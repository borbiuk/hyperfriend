# Claude Code — Hyperfriend

@AGENTS.md

## Working rules

- Follow existing project conventions (code style, folder structure, naming, dependency management) unless explicitly instructed otherwise.
- Never refactor unless explicitly requested; apply only the changes directly required for the current request. Keep changes minimal, explicit, and localized.
- Always use a block `if-return` statement (avoid inline one-liners).
- All comments and documentation must be in English; answer in the same language as the question.
- Dependencies: only exact versions, never `^` or `~`. Install with `npm install -E <package>@latest`, then run `npm run check:versions`.
- Do not add attribution lines ("generated by", co-author trailers) to docs, release notes or commit messages.
- Git safety: never run `commit`, `reset`, `rebase`, `push`, `pull --force`, `checkout --force`, `clean`, or `stash drop` unless the user explicitly asks; confirm before `git pull`, `git merge`, or `git stash`. The riskiest commands are also blocked or gated in [.claude/settings.json](.claude/settings.json).

## Agent context

- Rules (`.claude/rules/`) load automatically when matching files are touched: architecture (with the "add a new shortcut" checklist), GitHub DOM selectors (page detection, copy button, avatars, keyboard shortcuts, toast), shared API (config schema, shortcut helpers, settings file), popup (tabs), Firefox, npm versions, docs and CI, agent context.
- Skill `/verify` (`.claude/skills/verify/`): exact versions, both builds, ESLint, type check, `npm run lint:docs`, `npm run lint:unused`, `npm run test:unit`, `npm run test:e2e` and `web-ext lint`.
- Skill `/release` (`.claude/skills/release/`, invoked by the user only): version bump, release commit and zips, then after confirmation push, CI and tag (the release workflow builds the zips and creates the GitHub Release).
- Skill `/store-assets` (`.claude/skills/store-assets/`): regenerates and checks the Chrome Web Store promo tiles and screenshots.
- Skills for tests: `/playwright` (`.claude/skills/playwright/`: writing, running and debugging the Playwright suite, Chrome extension specifics) and `/e2e-review` (`.claude/skills/e2e-review/`: the test standard and the review workflow). Tests follow [testing.md](.claude/rules/testing.md); commands: `npm test`, `npm run test:unit`, `npm run test:e2e` (a `dist` setup project builds `dist/` first), `npm run test:live` and `npm run test:snapshots` (network, on demand; CI runs `test:unit` and `test:e2e` on every push and pull request, and the daily `markup.yml` refreshes the snapshots and runs `test:e2e` and `test:live`).
- Subagents (`.claude/agents/`): `code-reviewer` (read-only review), `qa-engineer` (read-only verification), `e2e-reviewer` (read-only review of tests with `/e2e-review`), plus the generated Playwright agents `playwright-test-planner`, `-generator` and `-healer` (regenerate with `npx playwright init-agents --loop=claude --project=e2e` after a Playwright update; their output must pass `/e2e-review`).
- Plugin `modern-web-guidance` (enabled in `.claude/settings.json`) provides the official `chrome-extensions` skill for Chrome APIs.
- MCP servers (`.mcp.json`): `chrome-devtools` loads the unpacked build into Chrome for in-browser checks; `playwright-test` serves the Playwright test agents. `init-agents` overwrites `.mcp.json`, so re-add `chrome-devtools` after running it.
